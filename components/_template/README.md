# Implementation brief

## Goal

What should the app or component do? Start with one behavior, not an entire software suite.

## Inputs and outputs

Specify formats, limits, error behavior, and user-visible results.

## References and permissions

List exact source URLs, target versions, authorization, and license constraints. Distinguish independent behavior notes from code permitted for reuse.

## Acceptance tests

List normal, edge, and failure cases and the expected results.

## Implementation

Choose the language and framework after defining the use case. Record dependencies and tested versions.

## Publication check

- Original or license-permitted code and assets only.
- Required notices included.
- No target binaries, private evidence, secrets, or personal data in files or history.
- Reproducible build/test instructions.
- Honest limitations and a data-export path where relevant.
